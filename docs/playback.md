# 播放器与恢复机制

## 原生播放

GSYVideoPlayer 14.0.0 和配套 Media3 1.10.1 通过 UTS/Kotlin 接入。正常播放继承 GSY 的 `Exo2PlayerManager`，播放、暂停、进度、缓冲策略和控件状态沿用官方实现。扩展层配置 MediaSource / 缓存，观测首帧、缓冲和下载表现。

重试和切集复用 Activity，每次使用新的会话 ID，过滤旧请求的迟到事件。起播并行启动 HLS 清单预取和媒体缓存索引准备。预取只读取当前主清单及一个关联子清单，不创建额外解码实例；结果未完成、无效、取消或过期时立即走常规加载。缓存实例在加载线程获取，避免 UI 等待磁盘索引。

## 来源与目录

首次默认西瓜，之后恢复上次片库；设置中可选自动模式或固定片库。目录、搜索、详情和播放默认使用同一来源；收藏、历史和进度保存在本机并绑定来源。

分类按片源父子层级读取。仅接受精确分类 ID 的接口会合并父级及各级子分类，按更新时间去重并继续分页；接口已包含子分类时沿用其分页。快速切换取消旧请求，取消加载更多不消耗下一页。

配置从 video_freevip 静态清单提取，不执行远程脚本。GitHub 直连失败后尝试 gh-proxy.com；双快照保存配置，失败保留最近有效版本。更新不重选当前正常片库，也不改变播放中的配置快照。

## 播放恢复

自动模式中，无结果搜索只尝试一个备选，有结果才切换。播放问题触发后台恢复：优先已确认映射，再用别名、季数、年份、演职员和共享豆瓣 ID 确认同剧。确认同集且备用视频通过验证后接力；只确认同剧时进入选集详情；不确定时保留原状态。

六秒是优化目标。后台验证上限初设十二秒，最多两个候选共用；就绪后的进度对齐最多再用五秒，条件满足立即提交。候选需解出首帧、有至少三秒可播缓存、实际网络下载余量约为播放码率两倍，才返回就绪。

准备实例使用独立管理器和媒体线程，不抢占当前音频焦点。预加载走网络并保存在内存，避免等待当前流的磁盘缓存锁；接力复用实例和缓存，后续继续用磁盘缓存。失败保留原进度。本机 D-UCB 记录仅用于挑选替代源，只有真实操作进入长期反馈。

## 数据与验收

0.2.0 首次启动一次性清除旧方案本机记录及本应用旧网页登录状态，不迁移旧数据、不访问网盘。

历史手机验收资料保存在本机 `artifacts/0.2.0/`；TV 模拟器记录在 `artifacts/tv/TV-verification.md`，不随源码提交。短样本不能证明整集流畅，模拟器结果不能代替真机验收。
